# Starting from zero

For users who cannot honestly claim a prior result with numbers. New graduates, career switchers, people whose past work is under NDA, or anyone whose history does not translate.

Doing outreach in this state wastes the user's limited pool of first-conversations on messages that had no chance. Fix the input first.

## Two paths

Two ways out of the cold start. Both take two to eight weeks. Pick the one that fits the constraints.

### Path one: manufacture a small, real, provable case

Find one problem in the target market solvable unilaterally — no client, no permission — and solve it publicly.

By wedge type:

- Growth — run a public experiment on a public asset (a small brand's account, a friend's Shopify store, an open-source project's landing page), measure, write it up with the numbers
- Engineering — build a small tool that solves a real problem for a real segment, ship it, measure usage, write up the technical calls
- Product — do a deep public teardown of a poorly designed app in the target segment, propose specific changes with mockups, publish
- Sales — run outbound for a small business owner in the user's network for free for four weeks, measure meetings booked, write up what worked

Rules:

- Real work, not hypothetical. A "here is what I would do" post is not a case study.
- Measurable and honest. If the number is small, say the number is small — the demonstration is the *method*, not the magnitude.
- Public. A private case study helps no one.
- Two to four weeks. If it drags, the scope is wrong.

Output: one real result with a number, publicly documented, that becomes the evidence in every downstream conversation.

### Path two: apprentice for a specific practitioner

Find one operator doing the exact work the user wants to do. Ask to run point on one specific project of theirs for free, four to eight weeks, in exchange for the user being able to name the operator as a reference afterwards.

Rules:

- One operator, not five. Diffuse apprenticeship is not apprenticeship.
- Specific project, not "shadow you for a month" — the operator will not have time. A defined project they were going to do anyway is easy to say yes to.
- Real deliverable, not busy work. If the ask is fetching and sorting data, walk.
- Reference agreement in writing, even informally. That is the payoff.

Output: one named operator willing to vouch for the user by name, plus one concrete piece of work the user can point at.

## Which path fits

- Time available, no income pressure — path one (public work compounds)
- Need to accelerate credibility inside an existing network — path two (referrals compound)
- Confident about the wedge, missing proof — path one
- Uncertain about the wedge — path two (proximity to an operator resolves the wedge question faster than solo work)

Users can run both in parallel if bandwidth allows. If forced to pick, pick one and finish it.

## Anti-patterns

- Getting a certification. No founder cares about certifications for this class of work. Skip.
- Cold-DMing "can I intern for you" without a specific project proposal. Zero reply rate.
- Writing think-pieces on the state of the industry. Without a track record, there is no standing to write them.
- A "learning in public" thread of what the user is reading. Founders do not hire readers.
- A portfolio site. No portfolio replaces one real result.

## User has some evidence, but weak evidence

Common case: real prior work, but the user does not own the metric, the numbers are non-transferable, or the work was years ago. In order:

1. Schedule one reference call with a former manager who can attest to the specific claim.
2. Reconstruct the numbers from memory, name them as reconstructed, and offer to put a former colleague on a call to corroborate.
3. Add a small new piece of work (path one) alongside the older evidence.

Never: exaggerate the metrics, take credit for team wins as individual wins, or vague-post about "impact" without numbers. The market checks.

## Handoff back to the main loop

Once a path produces a real, provable case, return to the wedge workstream, refit the claim around what actually worked, then begin map, signal, and outreach.
